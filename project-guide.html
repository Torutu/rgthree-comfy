Inside rgthree-comfy

rgthree-comfy is a ComfyUI extension with two halves: Python nodes that run inside ComfyUI's server, and a TypeScript layer that reshapes the graph editor in your browser. 01

Project overview

ComfyUI is a node-graph editor and execution server for image-generation models. You wire nodes such as a checkpoint loader, a text encoder and a sampler into a workflow, press Queue, and the server runs the graph. A custom node pack is a folder placed in ComfyUI/custom_nodes/ that adds node types and, optionally, JavaScript for the editor. rgthree-comfy is one of these packs; you install it with a plain git clone into that folder .

The README describes it as nodes and improvements the author made "to make my workflow cleaner, easier, and faster" . In practice it targets three problems that appear as ComfyUI graphs grow:

  • Too many wires. Context nodes carry up to 22 values on a single link. Reroute, Node Collector, Bookmark and Label tidy and navigate large canvases.
  • Too much clicking to switch parts of a workflow on and off. Fast Groups Muter and Bypasser, Fast Muter and Bypasser, the Mute/Bypass Repeater and Relay, Fast Actions Button and Random Unmuter turn node modes into dashboards.
  • Primitives that are too weak. Seed picks a random seed per queue and records it in the image metadata; Power Lora Loader stacks many LoRAs in one node with Civitai info; Power Prompt, Power Primitive and Power Puter (a Python-like expression evaluator) replace chains of small utility nodes.

On top of the nodes it changes the editor itself: a progress bar, "Queue Selected Output Nodes", auto-nesting of long menus, mute and bypass toggles in group headers, drag-and-drop import of one node's widget values, a settings dialog, and a standalone page that repairs corrupted workflow links.

Who uses it, and who builds it

The users are ComfyUI users who build and share workflows; the README is written for them and documents each node from the canvas side. The builders are mostly one maintainer: the account rgthree authored 389 of the 456 commits on main. The rest are community pull requests, and recent merges show what outside contributors typically fix: Power Puter edge cases, a path check in the userdata helper, and node modes being restored incorrectly when a workflow loads (git log, Sept to Oct 2026).

How the two halves fit together

The Python half registers 24 node classes with ComfyUI through NODE_CLASS_MAPPINGS and adds HTTP routes under /rgthree/ . ComfyUI's executor calls those classes when a prompt runs.

The browser half lives in web/comfyui/, which __init__.py exposes as WEB_DIRECTORY . It registers ComfyUI extensions that swap ComfyUI's generic node classes for richer rgthree classes, adds frontend-only virtual nodes that never reach the server, and patches functions in ComfyUI and LiteGraph (the canvas library ComfyUI is built on).

The halves meet in three places: the prompt sent when you press Queue (widget values become Python keyword arguments), the results a node sends back for display, and rgthree's own HTTP and websocket messages. Section 6 traces each of them.

The one idea to hold onto

A large share of this codebase hooks into code it does not own. Modules replace methods on ComfyUI's app and api objects and on LiteGraph prototypes as soon as they load. The comments mark these spots with [🤮] for workarounds and [⭐] for enhancements . When something breaks after a ComfyUI update, those markers are where to look first.

Repository structure

The repository holds a Python package, the TypeScript sources for the browser code, and the compiled browser code itself. The most important fact about the layout: you edit src_web/, the build writes web/, and web/ is committed because ComfyUI users install straight from git with no build step.

Names that mislead

Do not trust file names alone. These are the surprises I found while reading the implementations:

  • py/sdxl_power_prompt_postive.py is spelled "postive". Imports depend on the misspelling , so renaming it is a breaking change for nothing.
  • py/context_merge.py and py/context_merge_big.py open with the docstring "The Context Switch (Big)." They implement Context Merge.
  • prestartup_script.py does nothing today; its only statement is commented out . Git history shows it once patched ComfyUI's recursive execution (commit ec3b3b9, Sept 2023), later moved and then removed.
  • requirements.txt is empty and pyproject.toml declares dependencies = [] . The code still imports torch, numpy, aiohttp and requests; it relies on them being present in ComfyUI's environment.
  • src_web/scripts_comfy/*.ts contain only declare statements. They let TypeScript type-check import {app} from "scripts/app.js"; the build deletes their output and rewrites the import to ComfyUI's real file .
  • py/dynamic_context.py passes add_type as its flexible input type; that name is imported from Python's standard mimetypes module . It looks like an editor auto-import Inferred. The node is unreleased, so it has not mattered.

How src_web becomes web

__build__.py is the whole build system. Read it once; it is 151 lines. Each run deletes web/ and recreates it in five steps:

  1. Optional --fix. Rewrites source files in src_web/, appending .js to import paths that lack it . Browsers need the extension; TypeScript does not add it.
  2. Copy. rmtree(web), then copy src_web to web while skipping *.ts, *.scss and typings* . HTML, images, WASM and the tree-sitter JS arrive unchanged.
  3. Compile TypeScript. node ./node_modules/typescript/bin/tsc with tsconfig.json: rootDir src_web, outDir web, target ES2019, strict mode .
  4. Prune. With -t/--no-tests, delete the compiled tests; always delete web/scripts_comfy . A plain ./__build__.py keeps the tests (they are git-ignored); __commit__.py calls build() whose default removes them.
  5. Sass, then import rewriting. Each .scss becomes a sibling .css . Then every compiled .js has its rgthree/… and scripts/… imports turned into relative paths with the right number of ../ .
Pitfall

Editing anything inside web/ by hand is lost on the next build, because step 2 deletes the folder. The reverse mistake is just as common: editing src_web/ and forgetting to build, then wondering why ComfyUI behaves the same. ComfyUI only ever loads web/.

03

Architecture and module relationships

Code and data live in three places: the browser tab that runs ComfyUI's editor, the ComfyUI server process, and the disk next to it. Two remote hosts appear as well: Civitai, for LoRA and checkpoint metadata, and comfy.rgthree.com, for the logo.

  • Config travels as a JavaScript module. The browser imports /rgthree/config.js, and Python answers with export const rgthreeConfig = {…} built from the merged settings .
  • Model info (LoRAs and checkpoints) is read from a sidecar file next to each model, <model>.rgthree-info.json, and enriched from the safetensors header and from Civitai's by-hash API . Downloaded data is cached under userdata/info/ .
  • Pushes go the other way when model info changes: the server sends a rgthree-refreshed-loras-info (or -checkpoints-info) message on ComfyUI's websocket .
  • Pages: the link fixer at /rgthree/link_fixer, and a models page that is only routed when unreleased.models_page.enabled is set .

Two ways a server node gets its UI

ComfyUI generates a JavaScript class for every Python node it learns about. rgthree-comfy changes those generated classes in one of two ways, and you will meet both:

  1. Patch the generated class. Inside the beforeRegisterNodeDef hook, wrap methods on nodeType.prototype such as onNodeCreated and onExecuted. Display Any and the Power Prompt family do this, and the drag-and-drop widget import patches every node type the same way .
  2. Replace the generated class. Register an rgthree class as the replacement, then intercept LiteGraph.registerNodeType so LiteGraph receives the rgthree class instead . Seed, Power Lora Loader, Power Puter, Power Primitive, Any Switch, the Context family, Image Comparer, Image Inset Crop and Image or Latent Size use this.
Why replace instead of patch

Commit cc23fe1 (Oct 2023) is titled "Divorce Context nodes from ComfyNode implementation to fix instability with inputs, types, and widgets." The class comment says the same: "if comfyui is going to keep breaking widgets and inputs, it seems safer than NOT overriding" . The cost is spelled out too: other extensions' beforeRegisterNodeDef changes land on the discarded ComfyUI class, not on the rgthree one . To soften that, rgthree re-dispatches nodeCreated to other extensions itself, skipping a blocklist of known-bad ones .

04

Application startup and execution flow

There are two startups to understand: Python's, when the ComfyUI server boots, and the browser's, every time someone opens or refreshes the editor. A third flow, executing a queued prompt, is traced end to end in section 6.

When the ComfyUI server starts

  1. ComfyUI runs each pack's prestartup_script.py before loading nodes Inferred. This one is empty in effect.
  2. ComfyUI imports the package, which executes __init__.py top to bottom. After importing ComfyUI's own execution module, its first import from this package pulls in py/log.py, which imports py/pyproject.py; that module reads the version and name from pyproject.toml and raises if the logo URL is not an SVG .
  3. py/config.py runs refresh_config() at import time . It loads rgthree_config.json.default (JSON with // comments), loads the user's rgthree_config.json if present, migrates four legacy keys and rewrites the user file if it migrated anything, then merges: the defaults define which keys exist, the user file supplies values .
  4. Importing py/server/rgthree_server.py registers every rgthree route on ComfyUI's aiohttp router as a side effect of the decorators .
  5. The 24 node classes are imported and placed in NODE_CLASS_MAPPINGS, keyed by display name such as "Seed (rgthree)" . The key and the visible title are the same string; keep that in mind before renaming anything (section 9).
  6. If unreleased.dynamic_context.enabled is true, two more classes are added .
  7. WEB_DIRECTORY = "./web/comfyui" tells ComfyUI which folder of JavaScript to serve to browsers .
  8. Side effects worth knowing: it deletes two legacy install folders under ComfyUI/web/extensions/ if they exist , prints "Loaded N … nodes" (N comes from counting file names, not from the registry) , and prints the Nodes 2.0 compatibility warning unless the setting is off .

When the browser opens the editor

  1. ComfyUI's frontend loads every .js file under WEB_DIRECTORY as an ES module Inferred. Module top-level code runs first, and much of it patches globals immediately: LiteGraph.registerNodeType , api.getNodeDefs , LiteGraph.isValidConnection , LGraphNode.prototype.connectByType and LGraphCanvas.prototype.processKey .
  2. config_service.ts imports rgthree/config.js . Because it is a static import, every module that uses CONFIG_SERVICE can read settings synchronously from the first line.
  3. rgthree.ts creates the singleton rgthree and exposes it as window.rgthree . The constructor sets the log level, installs canvas and app hooks, injects rgthree.css, builds the progress bar and asks the server about known-incompatible extensions . The canvas menu hook waits 1016 ms before installing .
  4. Each node module calls app.registerExtension({…}). Server-node overrides implement beforeRegisterNodeDef(nodeType, nodeData) and call NODE_CLASS.setUp(nodeType, nodeData), which records the replacement . Virtual nodes implement registerCustomNodes() and register themselves directly .
  5. ComfyUI then calls LiteGraph.registerNodeType(name, ComfyClass); the patched version looks up the replacement map and registers the rgthree class instead (figure below).
  6. When a node instance is created, a server node builds its inputs, widgets and outputs from the Python definition , then calls onConstructed(), which announces nodeCreated to other extensions . A timer checks shortly afterwards that the subclass set its type and called onConstructed, and throws if not .

A node's life in the browser

  • Construct: constructor, then onConstructed() (see the steps above). Properties and widgets are guaranteed to exist .
  • Load: when a saved workflow is opened, LiteGraph calls configure(info). RgthreeBaseNode sets this.configuring = true around it ; nodes that propagate state check that flag so loading a workflow does not rewrite other nodes .
  • Live: connection changes call onConnectionsChange, mode changes call onModeChange (an rgthree addition, see section 7), and the canvas redraws widgets every frame through their draw() methods.
  • Save and queue: widgets turn into data through serializeValue ; nodes can adjust their saved JSON in onSerialize .
  • Copy: copy and paste go through clone(), which deep-copies properties .
  • Remove: onRemoved() sets this.removed = true ; debounced tasks check it before touching the node.

Context Switch returns the first ctx_* input that is not "empty", where empty means None or a dict whose values are all None . In the browser, context.ts makes dropping a link onto a context land on the right slot. It matches by type, and for CONDITIONING, INT, STRING, FLOAT and dropdowns also by name, using the node title to tell positive from negative .

Seedseed.ts · py/seed.py · rgthree.ts (api.queuePrompt hook)

The seed widget accepts three special values: -1 (random every queue), -2 (last seed plus one) and -3 (last seed minus one) . The node never changes its own widget when you queue. Instead it listens for comfy-api-queue-prompt-before, which rgthree.ts fires just before the prompt leaves the browser, and edits the outgoing data in place :

  • It writes the chosen seed into the API prompt (output[id].inputs.seed), which is what Python receives.
  • It writes the same seed into the workflow copy (widgets_values), which ComfyUI embeds in saved images. Dragging that image back in therefore reproduces the exact seed.
  • It remembers lastSeed and enables the "♻️ Use Last Queued Seed" button.

The comment above the handler explains why it edits the prompt rather than the widget: other extensions call graphToPrompt at unexpected times, and swapping widget values back and forth left the widget confused .

The Python side handles a client that sends -1 directly through the API. IS_CHANGED returns a fresh random number for special seeds so the node always re-runs , and main generates a seed, logs warnings, and patches it into extra_pnginfo and prompt so the saved image still records it . Random numbers come from a private generator state, saved and restored around each call, because some other extension seeds Python's global random . The range is 1 to 250; section 8 explains that number.

On the canvas

Every LoRA row is one custom widget named lora_1, lora_2, … whose value is a dict: {on, lora, strength, strengthTwo} . The row draws a switch, the file name, an info badge, one or two strength pickers and a × remove button, and records where it drew each part so clicks can be routed (hit areas, section 8). The "Add Lora" button, a header with "Toggle All", and spacer widgets are rebuilt around the LoRA rows on every configure .

When the "Show Strengths" property is "Single Strength", serializeValue drops strengthTwo, and Python uses one strength for both model and CLIP . Right-clicking a row opens a menu (Show Info, Toggle, Move Up/Down, Remove). Data flow and state management

Most bugs in this project sit on one path: from the moment you press Queue to the moment a result appears on a node. Learn this path first, then the places where state is kept between runs.

The queue path

  1. Queue pressed. rgthree's wrapper around app.queuePrompt sets rgthree.processingQueue = true and fires queue, then queue-end when the original finishes .
  2. Graph serialised. ComfyUI calls app.graphToPrompt(); the wrapper fires graph-to-prompt before and graph-to-prompt-end after . During this window Random Unmuter flips one input on. Each widget's serializeValue produces its data. A wrapper on LGraph.prototype.serialize keeps the latest workflow JSON so nodes can find their own entry in it . Virtual nodes do not appear in the result Inferred.
  3. Prompt sent. ComfyUI calls api.queuePrompt(index, {output, workflow}). rgthree's wrapper prunes output if specific nodes were requested, then fires comfy-api-queue-prompt-before with both objects, so listeners such as Seed can edit them in place . A second wrapper in PromptService records the returned prompt id .
  4. Server executes. ComfyUI validates the prompt, starts from the output nodes and works backwards. For each node it consults IS_CHANGED and the cache, then calls the class's FUNCTION with keyword arguments: widget values, upstream outputs, and any requested hidden inputs Inferred.
  5. Progress streams back. Websocket events reach PromptService, which emits progress-update for the bar .
  6. Results arrive. A returned {"ui": …} is delivered to that node's onExecuted(message); Display Any copies message.text[0] into its widget .
Pitfall: stacked wrappers

Two modules wrap api.queuePrompt: prompt_service.ts and rgthree.ts. The one installed last runs first. prompt_service.js is imported (through progress_bar.js) by rgthree.js, so it evaluates first and rgthree's wrapper ends up outermost Inferred. If you add a third wrapper, check where it lands in this chain and always pass the arguments through unchanged.

What the data looks like

Two JSON shapes travel together. The API prompt (output) is what Python executes: a map from node id to class name and inputs, where a two-item array means "output N of node X". The workflow is the editor's save format with positions, sizes, widgets_values, and a link table.

  • Links are two-item arrays [origin_id, origin_slot]; rgthree's pruning walks exactly these , and Power Puter's input_node() reads index 0 . That is why widget values must never be arrays .
  • _meta.title is what node('My Title') searches and what the progress bar shows .
  • In the workflow, each link is the array [id, origin_id, origin_slot, target_id, target_slot, type] .
  • Inside subgraphs, prompt ids are paths such as "5:12:5". The browser resolves them in getFullNodeIdFromApiPrompt and getNodeByIdFromApiPrompt ; Python mirrors the same walk in get_worflow_node . The TypeScript comment says the two must stay in sync.

WorkflowLinkFixer.check and fixsrc_web/common/link_fixer.ts · planning patches before applying them

check() walks the link table (in reverse) and, for each link, compares the three records. Instead of mutating the graph, it records intended changes in patchedNodeSlots, a shadow copy of the slots it has touched, and every later lookup consults that shadow first . This is the "plan, then apply" pattern: decisions about link 7 can depend on the planned fix for link 9.

  • Target says it holds the link but the origin does not list it → plan ADD on the origin.
  • Origin lists it but the target holds a different link → plan REMOVE from the origin; if the target's slot is empty, plan setting it instead.
  • One of the two nodes no longer exists → plan removing the dangling reference from the other.
  • Second pass: a link that neither side references after the planned patches → plan DELETE from the link table .

fix() applies the plan, runs check() again and recurses while problems remain, at most five more times .

Tensor shapes and the ×8 latent factor

A tensor is an n-dimensional array. ComfyUI passes an IMAGE as a tensor shaped [batch, height, width, channels], a LATENT as a dict whose "samples" tensor is [batch, channels, height ÷ 8, width ÷ 8], and a MASK as [batch, height, width] Inferred: these are ComfyUI's conventions, and the code here relies on them. Latents are 8 times smaller per side because the VAE compresses each 8 × 8 block of pixels into one latent position.

widthpx = 8 × widthlatent     heightpx = 8 × heightlatent
Worked example Checked

A latent with samples shape (1, 4, 128, 96) unpacks as count 1, channels 4, height 128, width 96, so the node returns (96 × 8, 128 × 8) = (768, 1024): WIDTH 768, HEIGHT 1024. An image shaped (1, 768, 1024, 3) returns (1024, 768).

Effect on behaviour. Image Resize converts between layouts before scaling: movedim(-1, 1) turns [B, H, W, C] into [B, C, H, W] for comfy.utils.common_upscale, and movedim(1, -1) turns it back . Power Puter's help text reads an image's width as a.shape[2] .

Common mistake, present in the code Checked

Unpacking a fixed number of dimensions. The browser lets you connect a MASK to Image or Latent Size , but a 3-D tensor reaches batch, height, width, channel = ….shape and raises ValueError: not enough values to unpack (expected 4, got 3). Exercise 2 fixes it. Also remember that a 5-D video latent would fail the 4-value unpack on line 27.

Aspect-ratio fitting: crop, pad and contain

Resizing to a box of a different shape forces a choice: fill the box and lose the overhang (crop, often called "cover"), fit inside and fill the gap (pad), or fit inside and return a smaller image (contain). The code compares two candidate sizes. With source size W × H and target w × h, scaling to the target height gives width h·W/H; scaling to the target width gives height w·H/W.

crop:    if h·W/H > w → resize to round(h·W/H) × h, then cut (excess) // 2 from each side
pad, contain: if h·W/H > w → resize to w × round(w·H/W); pad then centres it at ((w − OW) // 2, (h − OH) // 2)

If either target side is 0, the code computes it from the ratio and forces contain . In percentage mode the inputs are percentages of the source: round(width × W / 100) .

Integer range, precision and random state

Both halves cap random seeds at 250 = 1,125,899,906,842,624 . The reason is JavaScript: every number is an IEEE-754 double, which represents integers exactly only up to 253 − 1 = 9,007,199,254,740,991 (Number.MAX_SAFE_INTEGER). Staying at 250 leaves room for lastSeed + 1 to stay exact Checked.

range = (max − min) / (step/10)    seed = ⌊r × range⌋ × (step/10) + min,   r = Math.random() ∈ [0, 1)

The division by 10 undoes a LiteGraph/ComfyUI convention of storing number-widget steps multiplied by 10, so an INT widget with step 1 reports options.step = 10 Inferred.

Worked example Checked

With min 0, max 250, step 10 and r = 0.5: range = 250, seed = ⌊0.5 × 250⌋ = 562,949,953,421,312. Every integer in [0, 250) is equally likely; a result of −1, −2 or −3 (only possible with a negative randomMin) is replaced by 0.

On the server, random.randint(1, 2**50) is inclusive at both ends. The node keeps its own generator state: save the global state, restore its private one, draw, save the private one, restore the global one . That way another extension calling random.seed(42) cannot make "random" seeds repeat, which the comment says happened .

Common mistakes: seeds above 253 silently round in the browser while Python's integers are unbounded, so the two halves can disagree; and Math.random() is fine for seeds but not for anything security-related.

Floating-point steps

Binary floating point cannot represent 0.05 exactly, so repeated addition drifts. The strength arrows round to two decimals after each step . Dragging used to add deltaX × 0.05 per event without rounding ; it now measures from where the press started and rounds the same way (section 14).

Worked example Checked

Common mistakes: comparing floats with === or !=; and rounding only for display. Python's check strength_model != 0 treats a drifted 1e-17 as "on" Inferred.

Canvas coordinates and hit-testing

Three coordinate spaces meet in widget code. Screen space is CSS pixels in the browser window. Graph space is where node.pos lives; LiteGraph's pan-and-zoom object canvas.ds maps between the two using an offset and ds.scale. Node-local space has its origin at the node's top-left corner; a widget's draw(ctx, node, width, posY, height) and its mouse(event, pos) both use it. rgthree switches to a simplified drawing when ds.scale ≤ 0.5 .

Hit areas store bounds as either [x, width] (the full row height) or [x, y, width, height]. The test is inclusive on both edges:

hit = x ≤ px ≤ x + w  and (if 4 values) y ≤ py ≤ y + h
Worked example: a strength picker on a 300 px wide Power Lora Loader

The picker is drawn right to left. Its right edge is at 300 − 10 − 3.3 − 3.3 = 283.4. The parts are 9 (arrow) + 3 + 32 (number) + 3 + 9 (arrow) = 56 px wide , so drawing starts at 227.4: left arrow [227.4, 9], number [239.4, 32], right arrow [274.4, 9]. A click at x = 250 hits the number and opens a prompt; x = 278 hits the right arrow and adds 0.05.

The three-state toggle uses the row height h: knob radius 0.36h, track width 1.5h, knob centre at x + 0.5h (off), 0.75h (mixed) or h (on) . For a 20 px row that is a 7.2 px radius at offsets 10, 15 and 20.

Common mistakes: hit-testing with screen coordinates; computing bounds in draw() but forgetting to reset them when a part is hidden (Power Lora Loader sets hidden parts to [0, -1] ).

Modular arithmetic for rotation

Reroute stores where its input and output sit as names from ["Top", "Right", "Bottom", "Left"], in clockwise order . Rotating by 90° is "move one step around the circle", which is addition modulo 4. JavaScript's % keeps the sign of the left operand, so -1 % 4 is -1 Checked; the code adds 4 and takes the remainder again to stay in 0–3 :

new = ((index + d) % 4 + 4) % 4,    d ∈ {+1 (90°), −1 (−90°), +2 (180°)}
Worked example Checked

Top (0) rotated −90°: ((0 − 1) % 4 + 4) % 4 = 3 → Left. Left (3) rotated +90° → 0 → Top. Right (1) rotated 180° → 3 → Left. After changing the layout, width and height are swapped with setSize([h, w]).

Moving and resizing with the keyboard shortcuts snaps to a 10 px grid: Math.round(Δ / 10) × 10 .

Point-in-rectangle tests and grid sorting

A node belongs to a group when the centre of its bounding box lies inside the group's rectangle. The intervals are half-open (≤ on the left/top edge, < on the right/bottom), so a centre exactly on a shared edge belongs to only one of two adjacent groups :

(cx, cy) = (x + w/2, y + h/2)    inside ⇔ gx ≤ cx < gx + gw  and  gy ≤ cy < gy + gh

"Position" sorting reads groups like text: top to bottom, then left to right. To keep slightly misaligned groups in the same row, positions are first quantized to a 30 px grid :

row = ⌊y / 30⌋,   col = ⌊x / 30⌋;   sort by row, then col
Worked example Checked

Groups at C (10, 89), B (100, 95), A (40, 110). Rows: ⌊89/30⌋ = 2, ⌊95/30⌋ = 3, ⌊110/30⌋ = 3. C comes first; within row 3, A (column 1) precedes B (column 3). Result: C, A, B.

Common mistake: expecting "nearly level" groups to sort left to right. Quantization has hard boundaries at multiples of 30, so two groups 1 px apart can land in different rows.

zoom = min(current, Wcanvas/Wgroup − 0.02, Hcanvas/Hgroup − 0.02)

Binary search and common prefixes

fitString shortens labels to fit a pixel width. Measuring text is slow, so instead of trying every length it binary-searches the prefix length: halve the range of candidate lengths after each measurement . When no prefix fits exactly, the search returns the largest length that measured below the target.

Worked example, with a stand-in font of 7 px per character Checked

"detail_tweaker_xl_v2.safetensors" is 32 characters (224 px). For 100 px the target is 100 − 7 (the ellipsis) = 93 px; the longest prefix under it is 13 characters (91 px), giving "detail_tweake…". It took 5 measurements; a linear scan could take up to 32.

The LoRA chooser uses a longest common prefix. When the node's "Match" property filters the list, it strips the prefix shared by all matches so the menu shows short names, and adds it back to the chosen value . With matches styles/anime/ink.safetensors and styles/anime/oil.safetensors, the prefix is styles/anime/ and the menu shows ink.safetensors and oil.safetensors. The work is proportional to the total number of characters compared. With a single match the common prefix is the whole name, which used to leave an empty menu entry; chooserPrefix now backs off to the last folder separator Checked (unit test "chooserPrefix never turns a name into an empty menu entry").

Graphs, depth-first search and cycles

A workflow is a directed graph: nodes are vertices and links are edges from an output slot to an input slot. Execution needs it to be acyclic (a DAG); otherwise a node would depend on itself Inferred. Three algorithms recur in the code:

  • Depth-first search with a visited set to collect every ancestor of the chosen output nodes: recursiveAddNodes, cost O(V + E) .
  • Iterative depth-first traversal with an explicit stack to visit nodes inside subgraphs; children are pushed in reverse so they pop in their original order .
  • Path following through pass-through nodes (section 7), plus cycle prevention at connect time: before connecting A's output to B, the node checks whether B is already upstream of A.

Common mistakes: recursion without a visited set on data that might contain a cycle (infinite recursion); and treating node ids as unique across subgraphs. They are not, which is why caches key nodes by graphId:nodeId .

Hashing

A cryptographic hash maps any bytes to a fixed-size fingerprint: SHA-256 gives 32 bytes, written as 64 hex characters. Identical bytes always give the identical hash, so the hash identifies a model regardless of its file name. Civitai looks models up by it, and the local cache is keyed by it, so renaming a model file keeps its cached info . Hashing streams the file in 128 KiB chunks, so memory use is constant while time grows with file size.

Python's built-in hash() is a different tool: fast, not cryptographic, and for strings randomized per process. Two runs of python3 -c "print(hash('round'))" printed different numbers Checked. Power Puter builds its private built-in keys from hash(fn.name) ; that is safe only because the keys never leave the process. Never persist a value derived from hash().

Binary file formats and byte order

Multi-byte integers can be stored lowest byte first (little-endian) or highest byte first (big-endian). The project reads one of each:

  • safetensors: the first 8 bytes are an unsigned little-endian length N, followed by N bytes of JSON; training metadata sits under "__metadata__", and string values that look like JSON objects are parsed again .
  • PNG: an 8-byte signature (it starts 0x89 'P' 'N' 'G'), then chunks of [4-byte big-endian length][4-byte type][data][4-byte CRC]. The next chunk starts at offset + 12 + length. ComfyUI stores the workflow and prompt as text chunks, which the shim reads .
Worked example Checked

The bytes 40 01 00 00 00 00 00 00 read little-endian are 0x0140 = 320. The bytes 00 00 01 40 read big-endian are also 320. Read with the wrong order, the first would be about 4.6 × 1018.

Common mistakes: using the wrong byte order; and trusting length fields from a file. The safetensors reader rejects only lengths ≤ 0 before reading that many bytes.

Abstract syntax trees

Parsing turns source text into a tree that records structure and precedence. Python's ast.parse("a + b * 2") produces the tree below. An interpreter then evaluates it bottom-up: children first, then the operator at the parent. That is exactly what _eval_statement does for BinOp .

Boolean operators short-circuit and return an operand, not True/False, as in Python: 1 and 2 and 0 or 5 gives 5 Checked . f-strings are joined with str(), and format directives such as {x:.2f} are ignored, as the code comment warns .

Caching and IS_CHANGED

ComfyUI caches each node's outputs and re-runs a node only when its inputs, or the value its IS_CHANGED returns, differ from last time Inferred. So IS_CHANGED is a cache key:

  • Seed returns the seed itself (cacheable), or a fresh random number for −1/−2/−3 (always re-run).
  • Power Puter returns the constant 42 for deterministic code and time.time() otherwise. It decides by regex over the code after blanking string literals and comments, so "node(" inside a string does not count .

Common mistake: returning something that changes on every run. The node then never caches, and because its output is "new", every downstream node re-runs too.

Timers, debouncing and blocking calls

The browser runs JavaScript on one thread. Work is scheduled with setTimeout and requestAnimationFrame and coordinated with promises. Patterns you will see:

  • Debounce: many requests within a short window collapse into one call. debounce(fn, ms) stores one pending promise per function ; the any-input base class does the same with schedulePromise.
  • Polling: stabilization every 500 ms per any-input node, and FastGroupsService every 500 ms.
  • Time-based caches: sorted group lists for 400 ms, node bounding boxes for 50 ms; log messages rate-limited by id in Python (at_most_secs) and in JS (logPartsOnceForTime).
  • Synchronous events: dispatchEvent runs every listener before it returns. That is what lets Seed edit the prompt inside comfy-api-queue-prompt-before before rgthree's hook sends it on Inferred.

On the server, aiohttp handlers are async def, which only helps if slow work is awaited. The model-info handlers call get_model_info, which hashes files and calls requests.get synchronously; while that runs, the event loop cannot serve other HTTP requests or websocket messages Inferred. Proposal Move the blocking work into a thread with loop.run_in_executor, and use a timeout of seconds, not 5000.

Layout and strength maths

Rows are laid out from right to left, so the name gets whatever width is left. With margin m = 10, gap g = 4, × width 18 and strength width S = 14 + 34 + 14 = 62:

x× = w − m − 18 − 2    xstrength = x× − g − S    label width = xinfo − g − (m + 1.5h + g)
Worked example Checked

For a 484 px row, 20 px high, with the info badge: × at x = 454, strength at 388–450 (◀ 388, value 402, ▶ 436), info at 367 (17 px), and the label from 44, 319 px wide. These are the numbers computeRowLayout returns; a unit test checks that no parts overlap at widths 300–700.

Strengths are stored with two decimals. A drag ignores the first 3 px, so a click that wobbles isn't a drag, and then moves 0.01 per pixel:

step(s, d) = round((s + 0.05·d) × 100) / 100     drag(s0, Δx) = round((s0 + (Δx − sign(Δx)·3) × 0.01) × 100) / 100 for |Δx| ≥ 3
Worked example Checked

step(0.1, +1) = 0.15, not 0.15000000000000002. drag(1.00, 63) = 1.00 + 60 × 0.01 = 1.60; the old code gave 4.15 for the same gesture. drag(1.00, 2) = 1.00 (dead zone).

Common mistakes: adding per-event deltas (they depend on how often events arrive); rounding typed values (the prompt keeps exactly what you type, such as 0.125); comparing floats with === without rounding first.

What deploy does, and how undo works

  1. Refuse unsafe targets. The install must sit inside a folder named custom_nodes and be rgthree-comfy according to its pyproject.toml . Source and destination must not be the same, nested, or a symlink/junction. The script also writes a temporary file in the repo and checks it doesn't appear in the install, which catches two different paths to one folder .
  2. Refuse a stale build. Any .ts newer than its .js stops the deploy . make deploy builds first anyway .
  3. Compare. SHA-256 of every file in the deployable set: root files __init__.py, prestartup_script.py, pyproject.toml, … plus the py/, web/, src_web/, docs/ folders. Test bundles, __pycache__ and user data are left out .
  4. Ask only when replacing a non-dev install (no marker file) .
  5. Back up and verify the backup file by file, then write manifest.json with every file's hash .
  6. Copy root files, and mirror the four folders with robocopy /MIR. A file the repo no longer has is deleted from those folders; it is listed beforehand and kept in the backup .
  7. Verify every deployed file against the repo, write .rgthree-dev-deploy.json (commit, dirty flag, backup id), and say whether to reload or restart .

Option A, restore. It picks the newest pre-deploy backup, checks it against its manifest, shows what will change and asks. It saves the current state as a pre-restore backup, so a restore can itself be undone, then mirrors the backup into the install and verifies it . restore-original picks the newest backup taken just before a deploy replaced a non-dev install .

Option B, reset to upstream. It uses its own clone of github.com/rgthree/rgthree-comfy and never touches your repo. It resolves the target to a full commit hash, refuses anything not in upstream main's history (git merge-base --is-ancestor), exports the files with core.autocrlf=false so you get git's exact bytes, checks the file count, and then backs up, mirrors and verifies . If the network fails, it stops before changing anything.

Build toolchain notes

  • The typings need a patch. On a clean npm ci, tsc reports 1225 errors, because @comfyorg/comfyui-frontend-types declares LiteGraph types without exporting them. Upstream edits the file by hand (commit 20f3c0e: "manually changing typedefs to export what we need"). scripts/patch-frontend-types.mjs does the same reproducibly: 0 errors Checked . __build__.py stops on any type error , so without the patch the build fails half-way and leaves web/ half-written.
  • Build in WSL. __build__.py turns paths into import prefixes with file.replace(f'{DIR_WEB}/', "") , which needs / separators, so dev.ps1 runs the build inside WSL Inferred (read, not run on Windows). npm run build fails on Linux, as noted in section 11.
  • Two Nodes in WSL. Non-interactive shells (wsl.exe -- bash …) skip ~/.bashrc and found /usr/bin/node v20, which cannot run TypeScript tests. wsl-run.sh loads nvm's default Node first .
  • Line endings. Most source files are stored with CRLF, and there is no .gitattributes. Editors and tools that save LF turn a three-line change into a whole-file diff. Check with git ls-files --eol <file>.
  • Two files always "change" after a build. web/comfyui/node_mode_relay.js and node_mode_repeater.js were committed with three comments that the build strips (removeComments). This is harmless: commit them or git checkout them.
